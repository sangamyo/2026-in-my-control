# 2026 In My Control

**Live demo:** https://2026-in-my-control.vercel.app

[![Deploy to Render](https://render.com/images/deploy-to-render-button.svg)](https://render.com/deploy?repo=https://github.com/sangamyo/2026-in-my-control)

The backend deploys to Render from [`render.yaml`](render.yaml), and the frontend is on Vercel. On Render's free plan the API sleeps when idle, so the first request after a while can take about 50 seconds.


A full-stack habit and goal tracking dashboard. You define daily habits, check them off each day, and the app turns those check-ins into streaks, a yearly heatmap, trend charts and a rule-based "AI insight" report on your consistency.

## What it looks like

A dark, mobile-first dashboard with electric-cyan and neon-green accents. A sidebar (it collapses into a hamburger menu on mobile) links to three screens:

- **Dashboard ("Command Center")**: KPI cards for current streak, total check-ins, today's consistency % and your level. Below them sit a 7-day points line chart, a full-year contribution-style heatmap, the AI insight panel, a daily check-in list with previous/next-day navigation and a date picker, and a list of active habits.
- **Analytics**: a 7, 30 or 90-day range toggle, a completion-rate trend chart, a per-habit completion bar chart and a written consistency summary.
- **Settings**: add, pause/resume or delete habits, change your display name or password, and a "danger zone" button that resets all progress while keeping your habits.

## Features

- Email/password accounts with bcrypt password hashing and JWT authentication
- Per-user habits with daily check-ins (you can log past or future dates)
- Current and longest streaks, computed from the last 365 days of logs
- A 365-day activity heatmap and 7/30/90-day analytics
- A consistency report covering your strongest and weakest habit, streak risk (Safe / Caution / At Risk) and suggestions. It is generated by a heuristic engine in `backend/services/aiService.js`, and you can swap in an LLM there.
- A nightly cron job (00:05 server time) that saves a daily stats snapshot for each user
- A web app manifest for add-to-home-screen

## API

All routes are prefixed with `/api`. Everything except `/health`, `/auth/register` and `/auth/login` requires the `x-auth-token: <JWT>` header.

| Method | Route | Description |
|--------|-------|-------------|
| GET    | `/health` | Health check: `{ status, db, uptime }` |
| POST   | `/auth/register` | Create an account: `{ name, email, password }` returns `{ token, user }` |
| POST   | `/auth/login` | Log in: `{ email, password }` returns `{ token, user }` |
| GET    | `/auth/me` | Current user |
| PUT    | `/auth/profile` | Update `name` and/or `password` |
| DELETE | `/auth/reset-progress` | Delete all check-ins and stats (keeps habits) |
| GET    | `/habits` | List habits |
| POST   | `/habits` | Create a habit: `{ title }` |
| PUT    | `/habits/:id` | Update `title` / `active` |
| DELETE | `/habits/:id` | Delete a habit |
| GET    | `/checkin?date=YYYY-MM-DD` | Check-ins for a day |
| POST   | `/checkin` | Upsert a check-in: `{ habitId, date?, completed, score? }` |
| GET    | `/stats` | Streaks, totals, today's completion %, weekly points, level |
| GET    | `/heatmap?days=365` | Daily score series |
| GET    | `/analytics?range=7\|30\|90` | Completion trend + per-habit rates |
| GET    | `/ai-report?from=&to=` | Consistency report (defaults to the last 7 days) |

## Local development

Prerequisites: Node.js 18+ and a MongoDB instance (local `mongod`, Docker, or a free MongoDB Atlas cluster).

```bash
# 1. Backend
cd backend
cp .env.example .env        # then edit MONGO_URI / JWT_SECRET
npm install
npm run dev                 # http://localhost:4000 (nodemon)

# 2. Frontend (in a second terminal)
cd frontend
npm install
npm run dev                 # http://localhost:5173
```

In development the frontend calls `/api`, and Vite proxies it to `http://127.0.0.1:4000` (see `frontend/vite.config.js`), so you don't need a frontend `.env` locally.

Production build of the frontend: `cd frontend && npm run build` (output in `frontend/dist`).

## Environment variables

### Backend (`backend/.env`)

| Variable | Required | Default | Description |
|----------|----------|---------|-------------|
| `NODE_ENV` | Yes in prod | `development` | Set to `production` when deployed. Production startup fails if `JWT_SECRET` or `MONGO_URI` is missing. |
| `MONGO_URI` | Yes in prod | `mongodb://localhost:27017/goaltracker` (dev only) | MongoDB connection string |
| `JWT_SECRET` | Yes in prod | insecure dev-only value | Long random string used to sign tokens. Generate one with `node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"` |
| `CLIENT_URL` | Yes in prod | none | Allowed CORS origin(s), comma-separated, e.g. `https://your-app.vercel.app`. Outside production, `http://localhost:5173` is always allowed. |
| `PORT` | No | `4000` | HTTP port (Railway sets this automatically) |
| `JWT_EXPIRES_IN` | No | `7d` | Token lifetime (`jsonwebtoken` format) |
| `AI_PROVIDER` | No | `stub` | Placeholder for a future LLM provider |

### Frontend (`frontend/.env`)

| Variable | Required | Description |
|----------|----------|-------------|
| `VITE_API_URL` | Yes in prod | Backend API base URL **including `/api`**, e.g. `https://your-backend.up.railway.app/api`. If unset, it falls back to `/api` (the Vite dev proxy). Vite reads it at build time, so redeploy after you change it. |

## Deployment

### 1. Backend + MongoDB on Railway

1. Create a new Railway project and **Deploy from GitHub repo**, choosing this repository.
2. In the service settings, set **Root Directory** to `backend`. Railway picks up `backend/railway.json`, which configures the Nixpacks build, start command `npm start` (which runs `node server.js`), health check `/api/health` and restart on failure.
3. Add a database: **New → Database → MongoDB** in the same project. You can also use MongoDB Atlas.
4. Under the backend service's **Variables**, set:
   - `NODE_ENV=production`
   - `MONGO_URI=${{MongoDB.MONGO_URL}}` (Railway reference variable), or your Atlas connection string
   - `JWT_SECRET=<long random string>`
   - `CLIENT_URL=https://<your-vercel-domain>` (fill this in after step 2; separate several origins with commas)
5. Under **Settings → Networking**, click **Generate Domain** and note the public URL, e.g. `https://xyz.up.railway.app`.
6. Check that it's running: open `https://xyz.up.railway.app/api/health`. It should return `"db":"connected"`.

### 2. Frontend on Vercel

1. **Add New → Project** and import this repository.
2. Set **Root Directory** to `frontend`. Vercel detects Vite automatically: build command `npm run build`, output directory `dist`, install command `npm install`. The same values are pinned in `frontend/vercel.json`.
3. Add the environment variable `VITE_API_URL=https://xyz.up.railway.app/api`.
4. Deploy. `vercel.json` rewrites every non-asset path to `/index.html`, so deep links such as `/analytics` and `/settings` work on refresh.
5. Copy the Vercel domain back into the backend's `CLIENT_URL` on Railway. The backend redeploys automatically.

### Notes

- The nightly cron job runs inside the web process. Keep the backend at **one replica**, or move the cron into a separate worker, so the snapshot isn't written twice.
- Dates are bucketed by the server's local day. Railway runs in UTC.
